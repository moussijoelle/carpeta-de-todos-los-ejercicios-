Resumen de los temas — AJAX, APIs REST y manejo de errores

1. Asincronía en JavaScript

JavaScript ejecuta el código línea por línea, pero algunas tareas tardan (pedir datos a un servidor, esperar un temporizador). Para no bloquear la app, se usan tareas asíncronas.

Evolución

Método Problema
Callbacks Código anidado → "Callback Hell"
Promises Mejor, pero muchos .then()
Async/Await Se lee como código normal, con try/catch

Hoy se usa: async/await (sobre Promises). Los callbacks solo en APIs antiguas o librerías viejas.

2. APIs REST y JSON

Una API REST (como PokéAPI) es una forma estándar de pedir datos por internet.

3 reglas clave

  • Usa métodos HTTP: GET (leer), POST (crear), PUT/PATCH (editar), DELETE (borrar)
  • Cada cosa tiene su URL (endpoint): /pokemon, /pokemon/25 (Pikachu)
  • Es sin estado: cada petición es independiente; el servidor no "recuerda" quién eres

REST vs JSON: REST = las reglas del camino. JSON = el paquete con los datos que viaja.

Hoy se usa: fetch() (nativo del navegador) o Axios (más cómodo para errores). Casi todo en JSON.

3. try / catch / finally

Sirve para que un error no rompa toda la app.

try {
  // código que puede fallar
} catch (error) {
  // qué hacer si falla
} finally {
  // siempre se ejecuta (limpieza)
}

Buenas prácticas

  • No dejar el catch vacío → al menos console.error
  • No usarlo para validaciones simples → mejor un if

Hoy se usa: Igual. Es el estándar, sobre todo con async/await.

4. Errores propios con throw new Error

Puedes lanzar un error cuando una regla importante no se cumple (ej.: edad < 18).

if (edad < 18) {
  throw new Error("Debes ser mayor de edad.");
}

Hoy se usa: Sí, en reglas de negocio importantes. Para cosas simples (campo vacío), mejor un if sin throw.

5. Tipos de errores de JavaScript

Error Cuándo ocurre
TypeError Tipo incorrecto (ej. llamar un número como función)
ReferenceError Variable que no existe
SyntaxError Error de escritura en el código
RangeError Valor fuera de rango (ej. new Array(-1))
URIError URL mal codificada

El objeto error tiene error.name y error.message.

6. Casos típicos de try/catch

  1. JSON.parse — texto mal formado
  2. localStorage — almacenamiento lleno
  3. Peticiones HTTP — servidor caído, 404, sin internet

Con Axios, los errores van al catch y puedes distinguir:

  • error.response → el servidor respondió con error (404, 500…)
  • error.request → no hubo respuesta (sin red)
  • otro → error al preparar la petición

Hoy se usa: fetch + try/catch o Axios + try/catch. Ambos son habituales.

En qué consiste tu ejercicio (explicación en francés)

Bonjour !

Imagine que tu ouvres une application Pokémon sur ton téléphone. Tu vois plein de Pokémon, et tu veux pouvoir dire : « Celui-ci, je l'aime bien, je le garde dans mes favoris ».

C'est exactement ce que tu vas faire.

Étape par étape, sans jargon

  1. Tu vas chercher des Pokémon sur Internet
    Comme si tu ouvrais un livre géant sur Internet (la PokéAPI). Tu demandes : « Montre-moi des Pokémon », et le site te répond avec leurs noms, images, etc.
  2. Tu affiches ces Pokémon à l'écran
    Comme des cartes dans une galerie. Chaque carte a un bouton, par exemple « Ajouter aux favoris ».
  3. Quand tu cliques sur ce bouton, le Pokémon est sauvegardé
    Pas sur Internet — sur ton propre navigateur, dans une petite mémoire locale appelée localStorage. C'est comme un petit carnet dans ton navigateur : même si tu fermes la page et tu reviens demain, tes favoris sont toujours là.
  4. Tu montres la liste des favoris
    Une zone de la page où tu vois tous les Pokémon que tu as aimés.

Pourquoi tout ce qu'on a vu aujourd'hui est utile ?

Ce qu'on a vu Pourquoi c'est utile pour toi
API REST + fetch Pour récupérer les Pokémon depuis PokéAPI
async/await Parce que la réponse d'Internet met un peu de temps
try/catch Si Internet ne marche pas ou l'API est en panne, ton app ne plante pas — elle affiche un message
localStorage Pour garder tes favoris même après avoir fermé la page
JSON Le format dans lequel les données Pokémon arrivent

En une phrase :

Tu vas créer une mini-app qui charge des Pokémon depuis Internet, te laisse cliquer pour les mettre en favori, et sauvegarde cette liste dans ton navigateur pour la retrouver plus tard.

Résumé ultra-court : Internet → afficher Pokémon → clic → sauvegarder en local → afficher la liste des favoris.
