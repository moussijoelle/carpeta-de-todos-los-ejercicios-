Guide du projet carrousel — Exercice : créer les objets du carrousel avec des classes

Guide créé pour le projet du carrousel d'animes. Il explique l'exercice « Créer les objets du carrousel avec des classes » étape par étape, comme si la prof t'expliquait tout doucement.

1. De quoi parle l'exercice ?

Tu as une page web avec un carrousel : une image (ou du texte), un titre, une description. Tu peux passer au slide suivant avec les boutons › ‹.

Chaque « écran » du carrousel, c'est un slide :

  • la page d'accueil (portada, texte sans image),
  • les 20 animes (image + nom + description),
  • la page d'info à la fin (thème jour/nuit, lien Wikipedia).

Le problème de départ

Au début, les animes étaient écrits comme une liste désordonnée dans un seul fichier, sans modèle :

{ "Anime 1": { nombre: "City Hunter", imagen: "img/1.jpg", ... } }

Ça marche, mais ce n'est pas la méthode qu'on apprend en cours.

Ce que demande l'exercice

La consigne dit : créer les objets du carrousel avec des classes.

En une phrase :

Tu ne décris plus tes animes avec des objets bricolés ; tu as une classe Imagen, et chaque slide du carrousel est créé avec new Imagen(...).

Les 3 fichiers (comme la prof)

<script src="js/claseImagen.js"></script>  <!-- 1. la classe -->
<script src="js/datos.js"></script>         <!-- 2. les données -->
<script src="js/carrousel.js"></script>     <!-- 3. les opérations -->

Note : datos.js remplace imagenes.js du slide de cours — c'est le même rôle (les données), seul le nom du fichier change.

2. Les 3 définitions

claseImagen.js — La classe (le moule)

C'est le modèle qui dit à quoi ressemble un slide du carrousel. Une fiche vide avec des cases : image, nom, titre, description… On n'y met pas les vrais animes. On dit seulement : « Chaque slide aura cette forme. »

datos.js — Les données

C'est la liste de tous les slides du carrousel, remplis avec le modèle. Chaque ligne est un new Imagen(...). Les données du carrousel sont ici, pas dans les autres fichiers.

Ce ne sont pas « seulement les fichiers .jpg » — c'est chaque écran complet du carrousel (image + textes).

carrousel.js — Les opérations

C'est le fichier qui fait tourner le carrousel et affiche à l'écran. Il sait sur quel slide on est (0, 1, 2…), gère les boutons, l'autoplay, le thème, l'horloge, et met la bonne image et les bons textes dans la page.

Fichier En une phrase
claseImagen.jsLe modèle d'un slide
datos.jsLa liste des slides (new Imagen)
carrousel.jsLe fonctionnement et l'affichage

3. Exemple : City Hunter (slide n° 1)

claseImagen.js — le moule (pas encore City Hunter)

class Imagen {
  constructor(imagen, nombre, title, descripcion, puesto, episodios, ...) {
    this.imagen = imagen;       // chemin de la photo
    this.nombre = nombre;       // nom de l'anime
    this.title = title;         // style / genre
    this.descripcion = descripcion;
    this.puesto = puesto;       // ex: "Anime 1"
    this.episodios = episodios; // ex: 140
  }
}

4. Exemple : la portada (slide n° 0, sans image)

C'est la première page du carrousel : texte de bienvenue, pas de photo.

claseImagen.js — méthode esIntro()

esIntro() {
  // C'est la portada si : pas d'image, pas de title, pas de parrafoExtra
  if (this.imagen === "" && this.title === "" && this.parrafoExtra === "") {
    esPortada = true;
  }
  return esPortada;
}

datos.js — la portada est le premier élément

new Imagen(
  "",
  "Mapa del top 20 de mis animes japoneses preferidos",
  "",
  "Una exploración visual y técnica de las obras maestras..."
),

carrousel.js — affichage de la portada

  1. indexActual = 0
  2. slide.esIntro() → true
  3. pintarSlideIntro(slide) : bloc texte visible, photo cachée, message « Pulsa › para comenzar »

5. Pourquoi la intro utilise if et pas les autres de la même façon ?

Dans datos.js : toutes pareilles

Portada, anime et info sont toutes créées avec new Imagen(...). Là, pas de if. L'exercice des classes est le même pour toutes.

À l'écran : on ne peut pas tout afficher pareil

Le HTML a deux modes différents :

  • Intro : texte seul, pas de photo, message « Pulsa › »
  • Anime : grande photo + nom + description en bas
  • Info : texte + paragraphe extra + lien Wikipedia

On ne peut pas faire carouselImg.src = slide.imagen sur la portada car imagen est vide (""). On ne peut pas cacher la photo pour City Hunter car il a une image.

Donc dans carrousel.js :

if (slide.esIntro()) {
  pintarSlideIntro(slide);    // seulement du texte
} else if (slide.esInfo()) {
  pintarSlideInfo(slide);     // texte + paragraphe + lien
} else {
  pintarSlideAnime(slide);    // photo + données de l'anime
}

À retenir

  • Le if n'est pas parce que la intro est différente dans la classe — c'est parce que l'affichage change.
  • Les animes passent par le else : « si ce n'est ni intro ni info, c'est un anime ».
  • Si tous les slides avaient la même mise en page, une seule fonction suffirait — pas besoin de if.

6. Fonctions indépendantes — bibliothèque réutilisable

Après la refactorisation de carrousel.js, certaines fonctions sont indépendantes : elles reçoivent des paramètres, renvoient un résultat avec return, et ne dépendent pas du HTML de ce projet. Tu peux les réutiliser dans un autre exercice, comme dans ta bibliothèque de fonctions.

Critères d'une fonction « bibliothèque »

  • Tout arrive par paramètres
  • Le résultat sort par return
  • Pas de getElementById ni de variables globales du projet (imagenes, indexActual…)

Réutilisables avec la classe Imagen

  • obtenerTipoSlide(slide) — besoin de esIntro() et esInfo()

Fichier entier réutilisable

  • claseImagen.js — oui, le moule pour un autre carrousel
  • datos.js — non, ce sont tes 22 slides précis

Ces fonctions touchent le HTML de cette page ou les variables globales du carrousel :

Aujourd'hui ces fonctions sont dans carrousel.js, pas dans un fichier biblioteca-funciones.js séparé. Pour une vraie bibliothèque, il faudrait les extraire dans un fichier à part et les charger avant carrousel.js.
