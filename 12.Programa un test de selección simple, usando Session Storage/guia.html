1. ¿Qué es la persistencia?

La persistencia es la capacidad de guardar datos en el navegador para que sigan disponibles aunque recargues la página, navegues entre páginas del mismo sitio o, según el método, cierres y vuelvas a abrir el navegador.

En la web existen cuatro formas principales de guardar datos en el cliente. No son intercambiables: cada una tiene un propósito distinto.

2. Los cuatro tipos de almacenamiento

Session Storage Persistencia temporal

  • Duración: mientras la pestaña o ventana esté abierta.
  • Recarga (F5): los datos se mantienen.
  • Cerrar pestaña: los datos se borran.
  • Entre pestañas: no se comparten.
  • Capacidad: ~5 MB.
  • Uso típico: formularios largos, carrito temporal, estado de un test en curso.

Local Storage Persistencia local

  • Duración: hasta que el usuario borre datos o el código los elimine.
  • Cerrar navegador: los datos permanecen.
  • Capacidad: ~5–10 MB.
  • Uso típico: tema oscuro/claro, idioma, preferencias del usuario.

IndexedDB Persistencia masiva

  • Base de datos orientada a objetos, asíncrona.
  • Permite objetos complejos, archivos y grandes volúmenes.
  • Capacidad: muy grande (cientos de MB o más).
  • Uso típico: PWAs offline, editores, juegos con partidas guardadas.

Cookies Vinculadas al servidor

  • Capacidad: ~4 KB.
  • Clave: se envían al servidor en cada petición HTTP.
  • Uso típico: autenticación, sesiones de login, analytics.
  • Acceso mediante document.cookie.
Session Storage, Local Storage e IndexedDB nunca viajan al servidor. Solo las cookies se envían automáticamente con cada request.

4. Web Storage API — Métodos comunes

localStorage y sessionStorage comparten la misma API. Solo cambia cuánto tiempo viven los datos. 

// Guardar (sobrescribe si la clave ya existe)
sessionStorage.setItem("clave", "valor");

// Leer (devuelve string o null si no existe)
const valor = sessionStorage.getItem("clave");

// Borrar una clave
sessionStorage.removeItem("clave");

// Borrar todo
sessionStorage.clear();

// Cuántas claves hay — es PROPIEDAD, no método
console.log(sessionStorage.length);
Regla de oro: Web Storage solo guarda texto (strings). No guarda objetos, arrays ni números directamente.

5. Objetos y arrays: JSON.stringify y JSON.parse

JSON.stringify convierte un valor de JavaScript (objeto, array, número…) en una cadena de texto en formato JSON para poder guardarlo.

JSON.parse hace el camino inverso: convierte ese texto de vuelta en un valor usable en JavaScript. 

// ❌ MAL — pierdes los datos
const usuario = { nombre: "Elena", edad: 25 };
sessionStorage.setItem("datos", usuario);
// Guarda: "[object Object]"

// ✅ BIEN — serializar al guardar
sessionStorage.setItem("datos_usuario", JSON.stringify(usuario));

// ✅ BIEN — deserializar al leer
const datos = JSON.parse(sessionStorage.getItem("datos_usuario"));
console.log(datos.nombre); // "Elena"

Ejemplo con array

const miscanciones = ["Bohemian Rhapsody", "Billie Jean", "Hotel California"];

sessionStorage.setItem("lista_reproduccion", JSON.stringify(miscanciones));

const canciones = JSON.parse(sessionStorage.getItem("lista_reproduccion"));
console.log(canciones[1]); // "Billie Jean"
Método Dirección Para qué
JSON.stringify JavaScript → texto Guardar en storage
JSON.parse texto → JavaScript Leer del storage

6. JavaScript vs JSON — No son lo mismo

JavaScript

Es un lenguaje de programación. Sirve para dar lógica a la web: botones, formularios, tests, animaciones…

JSON

Significa JavaScript Object Notation. No es otro lenguaje ni una versión de JS. Es un formato de texto para representar datos. Solo sirve para guardar o intercambiar información, no para programar. 

// Esto es JSON (texto con estructura de datos):
{"nombre": "Elena", "edad": 25}

¿Dónde están las versiones reales de JavaScript?

Se llaman ECMAScript (estándar oficial del lenguaje):

ES6 / ES2015 let, const, clases, flechas =>, módulos
ES2016, ES2017… async/await y más mejoras anuales

8. Ejemplo práctico: tema oscuro con localStorage

Las preferencias de larga duración (como el tema) usan localStorage, no sessionStorage. 

// Al cargar (idealmente en el <head>)
const temaGuardado = localStorage.getItem('tema');
if (temaGuardado === 'dark') {
  document.documentElement.classList.add('dark');
}

// Al hacer clic en "Cambiar tema"
function cambiarTema() {
  document.documentElement.classList.toggle('dark');

  if (document.documentElement.classList.contains('dark')) {
    localStorage.setItem('tema', 'dark');
  } else {
    localStorage.setItem('tema', 'light');
  }
}
Cómo funciona Tailwind dark mode: clases como bg-white dark:bg-slate-900 definen dos estilos. Tailwind genera reglas del tipo .dark .dark\:bg-slate-900. Solo aplica el estilo dark: si un ancestro (normalmente <html>) tiene la clase dark. JavaScript solo enciende o apaga esa clase.

9. Conexión con tu ejercicio del test

Tu ejercicio es un test de selección simple con Session Storage. Encaja porque:

  1. Mantiene las respuestas si el usuario recarga por error (F5).
  2. Al cerrar la pestaña, el test se reinicia.
  3. Si guardas varias respuestas, usa un array u objeto con JSON.stringify / JSON.parse.

Flujo mental del test

Cargar página ↓ ¿Hay datos en sessionStorage? ↓ Sí ↓ No Restaurar estado Empezar test nuevo ↓ Usuario responde pregunta ↓ sessionStorage.setItem(..., JSON.stringify(respuestas)) ↓ Siguiente pregunta / Mostrar resultado

¿Cuándo usar cada almacenamiento?

Datos que el servidor debe recibir Cookies

10. Errores frecuentes que debes evitar

  • Guardar objetos o arrays sin JSON.stringify.
  • Olvidar JSON.parse al leer datos complejos.
  • Usar localStorage cuando necesitas datos solo de la sesión (o al revés).
  • Escribir sessionStorage.length() — es propiedad, sin paréntesis.
  • Asumir que Session Storage se borra al recargar — no se borra con F5.
  • Esperar compartir datos entre pestañas con Session Storage — no se comparten.
